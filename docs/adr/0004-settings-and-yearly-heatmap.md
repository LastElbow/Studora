# ADR-0004: Settings destination and full-year rolling heatmap

- **Status:** Accepted (2026-10-06)
- **Context:** Spec #2 adds two post-MVP surfaces. (a) A Settings surface whose first feature is a destructive "clear all study data". (b) A GitHub-style full-year heatmap that can navigate to past years ("past grids"). Open choices: where Settings lives (third bottom tab vs top-bar/overflow), how the heatmap window is modelled (rolling 52-week window anchored at `today.minusYears(N)` vs calendar years), and whether clear-all needs a Room schema change and the timer to be reset.
- **Decision:**
  - **Settings is a third bottom tab** (`Timer | History | Settings`), extending the sealed `Route` set and the `NavigationBar` from ADR-0003. Bottom navigation best practice is 3–5 destinations; Settings is expected to grow (roadmap: reminders, export/import), so a dedicated surface beats a top-bar overflow for one action.
  - **Clear-all deletes `completed_sessions` and the `in_progress` snapshot in one transaction.** The repository exposes `clearAll()` plus a `clears` signal; `TimerViewModel` observes the signal and returns to `Idle`, so a running in-memory session cannot re-record an entry after the clear. **No Room schema change or migration** is required — only a new delete query.
  - **The heatmap window is a rolling 52-week, Monday-first block.** Window `N` ends in the week containing `today.minusYears(N)`; window `0` is the current block ending this week. Windows do not overlap. Forward navigation is disabled at window `0`; back navigation is bounded by the earliest year that has data. This is chosen over calendar-year anchoring so every grid is a consistent 52-week block, matching the rolling GitHub default.
- **Consequences:** `Route`, `StudoraNavHost`, and the root `NavigationBar` grow to three destinations; ADR-0003's "two destinations" line is superseded. `SessionRepository` gains `clearAll()` and a `clears` flow; `HistoryUiState.Content` gains the window and navigation bounds. Rendering-only changes (grid, month/weekday labels) are reversible; the navigation shape and delete semantics are the hard-to-reverse parts and are recorded here.
